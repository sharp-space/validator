# SVL001: Validator is not registered by assembly scanning

| | |
| --- | --- |
| Severity | Warning |
| Category | Sharp.Validator |

## Message

> Validator '{0}' or its model is private, protected, or file-local, or nested in such a type, so AddValidators skips it; make them public or internal, or register it with AddValidator<T>()

## Cause

`AddValidators` registers an assembly's validators through its generated registrar whenever the assembly has one,
under the JIT as well as Native AOT, and generated code cannot name these types. Reflection scanning runs only for an
assembly with no registrar, and never under Native AOT, and it skips the same types, so the result does not depend on
whether the generator ran. A validator that is `private`, `protected` or `file`-local (or nested in such a type), or
whose model type is, is therefore left out of registration. An application that resolves `IValidator<T>` then gets no
validator: a lookup of `IEnumerable<IValidator<T>>` silently skips validation and a required lookup throws.

SVL001 is not reported for such a validator when the code around it creates it with `new`, as in
`Include(new AddressValidator())`: that validator is used directly, not resolved from DI. The analyzer looks for the
creation in the validator's file when it is file-local, and otherwise in the type that declares the innermost private
or protected type around it. A protected validator created only in a derived type elsewhere is therefore still
reported.

## How to fix

Make the validator and its model type `public` or `internal`, or register the validator explicitly with
`AddValidator<T>()` from code that can name it.

```csharp
// Flagged: private nested validator.
public class UserEndpoint
{
    private sealed class UserValidator : Validator<User> { /* ... */ }
}

// Fixed
internal sealed class UserValidator : Validator<User> { /* ... */ }

// Or register it yourself, inside the type that declares it.
public class UserEndpoint
{
    private sealed class UserValidator : Validator<User> { /* ... */ }

    public static void AddValidators(IServiceCollection services) => services.AddValidator<UserValidator>();
}
```

## Suppression

SVL001 is a warning. Suppress it only when the consequence above is what you want.

```csharp
#pragma warning disable SVL001
// ...
#pragma warning restore SVL001
```

```ini
# .editorconfig
dotnet_diagnostic.SVL001.severity = none
```
