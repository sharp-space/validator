# SVL010: Use [GeneratedRegex] for a literal Regex pattern

| | |
| --- | --- |
| Severity | Info |
| Category | Sharp.Validator |

## Message

> Literal Regex pattern runs interpreted under NativeAOT; convert it to a [GeneratedRegex] method

## Cause

SVL010 is reported only in a project with `PublishAot` set to `true`. The package's `buildTransitive` props make the
property visible to the analyzer, so set it in the project file, as .NET recommends, rather than only on the
`dotnet publish` command line, or ordinary builds and the IDE never see it.

Under Native AOT a runtime-built `Regex` runs interpreted, because `RegexOptions.Compiled` is unavailable, and the
regex parser and interpreter stay in the binary. A `[GeneratedRegex]` partial method compiles to matching code at
build time.

## How to fix

Apply the code fix, which converts the literal pattern to a `[GeneratedRegex]` method and keeps the 2-second match
timeout. Both ignore case in the invariant culture, so the conversion keeps the rule's verdicts.

```csharp
// Flagged: the literal pattern runs interpreted under Native AOT.
Builder.Property(x => x.Code).Regex("^[A-Z]{3}$");

// Fixed (what the code fix produces, in shape)
[GeneratedRegex("^[A-Z]{3}$", RegexOptions.None, matchTimeoutMilliseconds: 2000)]
private static partial Regex CodePattern();

Builder.Property(x => x.Code).Regex(CodePattern());
```

## Trade-off

A `[GeneratedRegex]` is the fastest option on one thread, but it is one shared instance. .NET's `Regex` keeps one idle
runner per instance, so a shared instance stops scaling once threads overlap on it, while a literal pattern spreads
over one instance per core. Under sustained parallel load, such as a bulk `Parallel.ForEach`, the generated method
tops out near a single core's throughput. Ordinary request rates stay far below that limit.

Under the JIT the trade-off favors the literal pattern, which can also take `RegexOptions.Compiled`, so SVL010 stays
silent there, including in libraries marked `IsAotCompatible`.

## Suppression

SVL010 is informational. Suppress it only when the consequence above is what you want.

```csharp
#pragma warning disable SVL010
// ...
#pragma warning restore SVL010
```

```ini
# .editorconfig
dotnet_diagnostic.SVL010.severity = none
```
